# Contract and limits

The CLI takes a real `--root` directory and three root-relative JSON files: `--before`, `--after`, and `--contexts`. The context map is configuration: `{"schemaVersion":"1","contexts":{"https://example.test/context":{"@vocab":"https://example.test/vocab/"}}}`. A graph is `{"@context":"https://example.test/context","@graph":[{"@id":"urn:example:item","@type":"Thing","name":"Example","related":{"@id":"urn:example:other"}}]}`. Inline context objects are also supported. The local context object may define `@vocab` and term-to-absolute-IRI string mappings. An unmapped context URI or term yields `incomplete`; there is no remote resolution or provider call.

This is a deliberately limited JSON-LD comparison. Every entity needs a stable `@id` and nonempty `@type` string or array. Property values may be JSON scalars, unordered scalar arrays, a single `{"@id":"..."}` relationship, or an unordered array of those relationships. Equivalent term mappings and array/key reorderings compare equal. Duplicate IDs, nested value objects, scoped contexts, `@list`, language maps, and other JSON-LD features not represented by this subset are incomplete. The tool does not claim semantic RDF equivalence, dereference IDs, or verify that a release export is complete; callers must supply complete local releases. IDs and values are never copied to reports.

stdout is one JSON report with `schemaVersion`, `tool`, `status`, `summary`, and findings sorted by code unit on `(location.file, location.pointer, ruleId)`. `@before` and `@after` are logical provenance roles for the files named at invocation, with zero-based `/@graph/<ordinal>` pointers. Fixed messages do not echo identifiers or values. Exit 0 means complete and unchanged, 1 means complete with differences, and 2 means bad invocation or incomplete evidence. Bad options, root or context configuration leave stdout empty; unreadable release inputs produce an `incomplete` JSON report.

Limits: 262144 bytes per release file, 65536 context-map bytes, JSON container depth 4 for releases and 3 for contexts (root at 0), 500 entities per release, 10000 properties per release, 1000 values per property, and 5000 milliseconds from root resolution. N is accepted and N+1 is incomplete. All files use strict UTF-8 and realpath confinement inside the real root. The tool reads only the named files, writes nothing, and treats input text as data.

Stable error rules (differences): `entity-added`, `entity-removed`, `entity-types-changed`, `entity-fields-changed`, `entity-relationships-changed`. Stable warning rules (incomplete): `input-unavailable`, `input-invalid`, `input-too-large`, `depth-limit`, `record-limit`, `timeout`, `context-unknown`, `context-unsupported`, `entity-invalid`, `entity-duplicate`, `empty-graph`.
